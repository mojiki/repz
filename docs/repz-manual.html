01基本的な使い方

トップ画面から「記録する」「直近トレ」「体重」、右上のヘッダーから「使い方」「設定」。ログインはブラウザに保存すれば以降は自動。どのページも下部の「← Topに戻る」で一発でトップへ戻れる。

アプリ内の使い方ページ この章の内容はアプリ内の /help（ヘッダーの「使い方」）にも同じものを置いてある。技術スタックや運用の話（このマニュアルの 02 章以降）はアプリには出していない。

トレーニングを記録する

  1. 大分類かメニューを選ぶ
    胸・背中・脚・肩・腕・その他、または保存したメニューテンプレート。
  2. 種目を選ぶ
    手入力はなし。無い種目は設定画面で追加する。
  3. セットを入力する
    前回同じ種目をやったときの各セットの重量・回数が初期値で入っている。重量は −2.5 / +2.5、回数は −1 / +1 ボタン、直接入力も可。＋ セット追加で前回の対応セット（無ければ最後の行）をコピー。
  4. 保存する
    推定1RM が自己ベストを超えたセットには MAX更新! バッジが付く。メモ欄はその日全体の共通メモ。
推定1RM の計算 Epley 式 重量 × (1 + 回数 ÷ 30) を全セットで計算し、その最大値を自己ベストとして判定している（実際に1回挙げた重量ではなく推定値）。

トップ画面の構成

上から 今日トレ → 直近トレ → 今週のボリューム → 体重 の順。

  • 今日トレ … 今日ぶんを1件でも保存すると先頭に表示（何も記録していない間は非表示）。日付・その日のトータルボリューム・種目ごとの最大重量とトータルボリューム。
  • 直近トレ … 今日より前で最後にトレーニングした日の詳細へ。表示内容は今日トレと同じ形式。ここから編集・削除もできる。
  • 週間ボリューム … ボリューム＝重量 × 回数 の合計。週は月曜始まり。「今週 vs 前週」の合計と増減%。種目名をタップするとその種目の重量推移グラフ（MAX重量・推定1RM）。詳細画面では前週・翌週に移動できる。

体重

  • 日付（既定は今日、過去日も選択可）＋体重を記録。同じ日にもう一度記録すると上書き。
  • 推移グラフと、記録どうしの増減。一覧から個別に削除できる。

編集・削除（1日に複数回ジムに行ったとき）

セッション詳細（/session/日付）で:

  • 編集 … その種目のセット入力画面を、その日付として開く。
  • 種目を削除 … その日のその種目だけ削除。
  • この日に種目を追加 … 後から追記。2回目のジムぶんを1回目のセッションにまとめる用途。
  • このセッションを削除 … その日を丸ごと削除。

設定

  • 種目 … 大分類＋種目名で追加（同じ分類の同名は不可）。名前はフィールドを編集してフォーカスを外すと保存。▲▼ で大分類内の並び替え。削除するとその種目の過去記録も一緒に消える。
  • メニューテンプレート … 作成 → 編集画面で種目を追加・並び替え。記録時に「メニューから選ぶ」で一覧展開。
  • CSV エクスポート … トレーニング記録（日付・分類・種目・セット番号・重量・回数・ボリューム・メモ）と体重記録。UTF-8 BOM 付きで Excel でそのまま開ける。

05データの持ち方

テーブル内容主なカラム / 制約
exercises種目マスタcategory, name, sort_order ／ (category, name) は一意
workout_sessionsトレーニング日date（一意）, memo ／ 1日1件

セッションを削除するとその sets も消える。種目を削除するとその sets とテンプレート内の該当行も消える（カスケード）。

日付とタイムゾーン 日付は YYYY-MM-DD として扱い、DB には UTC 0時の日時で保存。「今日」の判定は環境変数 APP_TZ_OFFSET_MINUTES（既定 540 = 日本時間）で行う。この値を消すと UTC 扱いになり、深夜のトレーニングが前日に記録される。

06運用

ふだんのデプロイ

git push するだけ。Vercel が prisma generate && next build で自動ビルド・公開する。ビルドは DB につながないので、環境変数が無くても通る。

スキーマを変更したとき

  1. スキーマを編集
    prisma/schema.prisma を書き換える。
  2. ローカルに migration を作る
    npm run db:migrate（ローカルの SQLite に対して実行）。
  3. Turso に反映する
    PowerShell で:
    $env:DATABASE_URL = "libsql://….turso.io?authToken=…"
    npm run db:push-turso
    migration の SQL を libSQL 経由で Turso に流し、種目シードも流す。
  4. push する
    コード側（Prisma Client の型など）を git push して Vercel を更新。
prisma migrate deploy は使わない Prisma 7 のスキーマエンジンは libsql:// に接続できず P1013 で失敗する。Turso への反映は必ず npm run db:push-turso（＝scripts/setup-turso.ts）を使う。

環境変数（Vercel）

キー値
DATABASE_URLlibsql://repz-….turso.io
DATABASE_AUTH_TOKENTurso のトークン
BASIC_AUTH_USERログインID
BASIC_AUTH_PASSWORDログインパスワード
APP_TZ_OFFSET_MINUTES540

Vercel の Turso 連携を使う場合は TURSO_DATABASE_URL / TURSO_AUTH_TOKEN でも動くようにしてある。

Turso の URL とトークンの取り方

  1. turso.tech に GitHub でログイン。
  2. Databases → Create Database（名前 repz、リージョンは東京 nrt）。
  3. データベース詳細ページの「Connect」に出る libsql://… が URL。
  4. 同ページの「Create Token」で認証トークンを発行（画面を離れると再表示できないのでその場でコピー）。

バックアップ

Turso 無料プランに自動バックアップは無い。月1回、設定画面から CSV を2種類ダウンロードして保存する運用にしておくと安全。

07料金と注意事項

現状すべて無料枠。1人ぶんのトレーニング記録は数MBで、どのサービスの上限にも当分届かない。

サービスプラン月額上限・注意
VercelHobby¥0 個人・非商用のみ。人に売る/広告を出す等の商用利用は Pro（$20/月）が必要。帯域 100GB/月・関数実行時間などの上限があるが、個人利用では問題にならない。
TursoFree¥0 無料枠が広く（ストレージ数GB、月間の読み書き行数も桁違いに余る）、当分課金は発生しない。長期間アクセスが無いと DB がスリープ/アーカイブされることがある → 再アクセスで復帰。
GitHubFree¥0 private リポジトリも無料。制限で困ることはない。
ドメイン—¥0 *.vercel.app は無料。独自ドメインは任意（年 ¥1,500 前後）。

注意事項

  • 認証は1組の共有ID/PW。個人利用前提で、ユーザーごとのデータ分離はしていない。URL を人に教える＝そのままデータが見える。
  • 自動バックアップは無い。間違って全削除しても戻せない。定期的な CSV 保存が唯一の保険。
  • DATABASE_AUTH_TOKEN は秘密情報。漏れたら Turso ダッシュボードで再発行し、Vercel の環境変数も更新する。GitHub にコミットしない（.env は .gitignore 済み）。
  • APP_TZ_OFFSET_MINUTES=540 を消さない。消すと「今日」が UTC 判定になり日付が9時間ずれる。
  • 無料枠の内容は変わりうる。Vercel も Turso も過去に無料プランを変更している。年1回くらい最新の料金ページを見ておく。
  • GitHub アカウント akanagi2 を削除する前に、Turso のログインにそのアカウントを使っていないか確認する（使っていると Turso ダッシュボードに入れなくなる）。
  • Vercel Hobby は「コミット作者＝アカウント本人」しかデプロイできない。別アカウントのメールでコミットするとデプロイがブロックされる。git config user.email を Vercel 連携アカウントに合わせる。
