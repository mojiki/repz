# Repz 設計ドキュメント

## 1. 概要

ジムでのトレーニング中にスマホから記録できる、個人利用の筋トレ記録Webアプリ。
前回記録との比較、週間ボリュームの可視化、体重推移の記録を主目的とする。

- **利用形態**: Webアプリ(スマホブラウザ)、オンライン専用
- **利用者**: 1人
- **認証**: Basic認証(ホスティング側の機能で設定、コード実装不要)

---

## 2. 技術スタック

| 項目 | 選定 |
|---|---|
| フレームワーク | Next.js |
| DB | Turso (SQLite) |
| ORM | Prisma |
| ホスティング | Vercel |
| 認証 | Basic認証 (Next.js middleware) |

### 構成イメージ

```
[スマホブラウザ]
      ↓ Basic認証(ID/PW)
[Vercel上で動くNext.jsアプリ]
      ↓ Prisma経由でクエリ
[Turso (SQLiteのクラウド版DB)]
```

## 4. 画面構成

```
トップ画面
 ├─ 「記録する」ボタン → 大分類選択 → 種目選択 → セット入力
 ├─ 「直近トレ」ボタン → 前回の全メニュー・重量を表示
 ├─ 週間ボリューム表示(種目ごと)
 ├─ 総週間ボリューム比較(今週 vs 先週、後述)
 ├─ 「体重」→ 記録/推移グラフ
 └─ 「設定」→ 種目の追加・削除・並び替え、メニューテンプレート管理
```

### 4.1 トップ画面

- **記録するボタン**: 大分類選択 → 種目選択 → セット入力の導線。または保存済みの「今日のメニュー」テンプレートから一括展開も可能。
- **直近トレボタン**: 前回セッションの全種目・全セット・重量を一覧表示。
- **週間ボリューム表示**: 種目ごとの週間総ボリューム(重量×REP×セット数の合計)。月曜始まり。
- **総週間ボリューム比較**: 全種目合計ボリュームの「今週 vs 先週」比較。
  - 表示例: 「先週比 +8% ↑ (今週: 12,500kg / 先週: 11,600kg)」

### 4.2 セット入力画面

- 種目選択後、前回の同種目のセット記録(セット単位)がデフォルト値として表示される。
  - 例: 前回1セット目「60kg × 10rep」→ 今回の1セット目の初期値として表示
- **重量入力**: 数値入力 + 「+2.5kg / -2.5kg」ステッパーボタン
- **セット追加**: 「+セット」ボタンで前回の対応セットの値をコピーして追加
- **PR(自己ベスト)判定**: 入力値が過去の自己ベストを更新した場合、「MAX更新!」などのバッジを表示
- セッション単位の簡易メモ欄あり

### 4.3 体重記録画面

- 体重の記録(いつでも単独入力可能)
- 推移グラフ表示(ボタン押下で表示)

### 4.4 設定画面

- 種目の追加・削除
- 種目の大分類内での並び替え(表示順をよく使う順に調整可能)
- 「今日のメニュー」テンプレートの作成・編集・削除

## 5. 主要機能まとめ

| 機能 | 内容 |
|---|---|
| 種目選択 | 大分類 → 種目名の階層選択(手入力なし、固定リスト+設定画面から追加削除可) |
| 前回比較 | セッション単位(直近トレボタン)/ セット単位(種目入力画面) |
| 週間ボリューム | 種目ごと + 全種目合計、月曜始まり、今週 vs 先週の差分%表示 |
| 前回値の自動入力 | セット入力時に前回の同セット番号の値を初期値としてセット |
| 入力UX | 重量は+2.5/-2.5kgステッパー、セット追加は前回値コピー |
| PRバッジ | 自己ベスト更新時に表示 |
| メニューテンプレート | よく行う種目の組み合わせを保存し、ワンタップ展開 |
| 簡易メモ | セッション単位でフリーメモ |
| 体重記録 | 独立記録 + 推移グラフ |
| 編集・削除 | セッション/セットの事後編集・削除に対応(1日複数回利用時の統合にも使用) |
| グラフ | 種目ごとの重量推移(MAX重量推移)、体重推移 |
| CSVエクスポート | バックアップ用 |
| 認証 | Basic認証(Vercel + Next.js middleware) |

---

## 6. 不採用とした機能

- インターバルタイマー(次セットまでの休憩時間計測)
- オフライン対応(PWA化・オフラインキャッシュ)
- lbs単位切替
- 同一種目のウォームアップ/本セットの分別管理
- OAuthなどの本格的な認証(Google連携等)

---

## 7. 実装時の補足

- Prisma schemaで上記テーブル構成をまず定義し、`prisma migrate` でTursoに反映する想定。
- 週間ボリューム集計・前回比較のクエリはPrismaのクエリで実装(生SQL不要)。
- Basic認証はVercelデプロイ後、`middleware.ts` に数行追加するだけで有効化できる。
